План «ResultURL на MSK + синк гранта на DE без переноса polling» — отложен, отдельно. DNS и MSK-бот не включать без спроса.

## 2. Как устроено хранение (важно для аудита)

Живой источник правды задуман так:

| Слой | Путь / механизм | Роль |
|---|---|---|
| OperationalStore | `/root/tarolog/bot_state.sqlite3` → документ `users` (JSON payload + **revision**) | основной store |
| Зеркало | `user_data.json` | mirror |
| Кошелёк / связка | `shared_wallet.json` | MAX↔TG / wallet mirror |
| RAM | `UserData` в процессе `tarolog` | то, что реально читает UI |

Ключевые механики в коде (`_prod_work`, снимок + CURSOR-FIX локально):

- `UserData.extend_subscription(chat_id, days)` — **стек**:  
  `base = current_end if current_end > now else now`, затем `+ days`.  
  Два fulfill подряд на одного юзера → ~62 дня → в UI ~60/59.
- `set_subscription_end` помечает `_sub_dirty` и `save_data()`.
- Merge (`bot_core/user_state_merge.py`): если id в dirty — **RAM побеждает диск**; если не dirty — с диска можно подтянуть `subscription_end`.
- Следствие: правка только JSON/sqlite **без restart** часто бесполезна — бот в RAM держит старое и при save затрёт диск.  
  Правка диска + **restart** обязательна. Если после restart снова 59 — либо правка не попала в тот документ, откуда грузится старт, либо что-то снова сделало `extend`.

Python на сервере: **`/root/tarolog/venv/bin/python`** (system python без aiogram).

### 4.4. Безопасный фикс «59 → ~30» (если диск ещё ~60)

Не `extend` ещё раз. Нужен **set absolute end**:

1. Вычислить `T = now + 31 days` **или** зафиксировать явную дату (как раньше `2026-12-07 19:04:05`), одну на админа.
2. Записать **во все зеркала**, которые бот грузит при старте (+ `revision+1` в sqlite).
3. `systemctl restart tarolog`.
4. Сразу перечитать диск; попросить владелицу заново открыть «🎁 Бонусы» (не смотреть старое сообщение в чате — оно не обновляется само).
5. Если снова 59 — искать: второй процесс бота, другой `WorkingDirectory`, другой sqlite path в unit, запись из wallet merge, повторный fulfill.

Команда unit’а: проверить `systemctl cat tarolog` — куда указывает `WorkingDirectory` / `ExecStart`.
